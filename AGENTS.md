## Согласованный объём

Локальная Windows-программа. 3 исходника в день × 6 аккаунтов (3 TikTok + 3 YouTube) = 18 вариантов и 18 публикаций. Первая версия: баннер, варианты с фильтрами, публикация, расписание и статистика. Gemini — последующий этап.

Стек утверждён: Python, FFmpeg/ffprobe, FastAPI, React + TypeScript + Vite, SQLite + SQLAlchemy, APScheduler и отдельный рабочий процесс. Rust, Streamlit, Redis, PostgreSQL и Docker для старта не требуются.

Основной запуск по запросу от 25 октября — отдельное окно Windows pywebview/WebView2. Закрытие окна не останавливает worker. TikTok: интерактивный вход и сохранённая сессия (`browser_login`) не равны проверенной автопубликации (`browser_verified`); не снимай защиту отправки только из-за успешного входа.

Интерфейс утверждён: работаем только над классической тёмной «Монтажной». Desktop-рабочая область от 1024×600 должна вмещать редактор целиком без вертикальной прокрутки и наложений. Основные области остаются видны, настройки переключаются вкладками, дополнительные параметры — в диалогах, длинные списки — страницами. Не возвращай отклонённые альтернативные компоновки без запроса пользователя.

Перед изменениями интерфейса читай `docs/design/DESIGN_SPEC.md` — утверждённую дизайн-спецификацию v1.0. Эталонные HTML, токены и 8 снимков хранятся в `docs/design/assets/design-v1/`, их контрольные суммы — в `manifest.json`. Не перезаписывай замороженный эталон молча; новые согласованные решения фиксируй новой версией. Копия дизайн-спецификации для пользователя — `06 - Дизайн — спецификация.md` в Obsidian; при изменении документа синхронизируй её с сохранением пользовательских правок. Демоочередь/авторизация/метрики эталона не считаются реализацией backend.

Работа с реальными аккаунтами требует доступов пользователя. Наличие этих правил не является разрешением публиковать конкретные материалы: до тестовой отправки согласуй с пользователем материал, аккаунт и видимость, если это ещё не указано. Независимую локальную работу продолжай без ожидания доступов.

## Уточнение 26 октября — основной режим автозалива

По явному запросу пользователя кнопка «Запустить автозалив» в диалоге с материалами, каналами, видимостью и временем разрешает рендер и отправку без второго подтверждения после MP4. Это действие выполняет сам пользователь. Не включай автозалив старым заданиям и не нажимай отправку реальных материалов самостоятельно без ранее указанного материала/аккаунта/видимости. Сохранены проверки browser_verified, БУБА, unknown без повторов и пользовательские подтверждения содержания. Ручной режим MP4 остаётся доступен при выключенном флажке. Инструкция Obsidian: «14 - Автозалив одним запуском.md».
