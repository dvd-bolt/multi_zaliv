# Реализация 0.1 — границы текущего результата

Дата: 25 октября 2026, Europe/Moscow. Это описание устройства реализации; единственная дорожная карта остаётся в Obsidian.

## Модули

`backend/app.py` — локальный API и выдача собранного React-приложения. `db.py` — SQLite WAL, внешние ключи, начальная миграция. `schemas.py` — проверка параметров. `media.py` — анализ, миниатюры, воспроизводимые фильтры и экспорт FFmpeg. `queue.py` — неизменяемые снимки настроек, защита от одинаковых заданий и переходы состояний. `worker.py` — отдельный процесс APScheduler, один исполнитель, блокировка от второго worker. `platforms.py` — границы OAuth/публикации/метрик. `vault.py` — Windows DPAPI. `maintenance.py` — копии базы и ограниченная очистка.

React обращается к реальным локальным данным. Рабочие файлы, аккаунты и метрики при первой установке отсутствуют; тестовые данные создаются только в отдельной тестовой папке. Шрифты входят в сборку и не требуют Google Fonts. Статический эталон дизайна v1.0 сохранён без изменений.

## Жизненный цикл

Очередь хранится в SQLite. Задание ссылается на отдельный вариант, исходник и аккаунт. Настройки копируются в момент постановки; дальнейшее редактирование не меняет готовящийся материал. Ключ варианта учитывает SHA256 исходника/баннера, аккаунт и настройки. Повторная постановка тех же параметров возвращает существующее задание.

`queued → rendering → ready`. Результат пишется во временный `.part.mp4`, проверяется ffprobe и переименовывается. Отмена удаляет промежуточный файл. После аварии `rendering` возвращается в `queued`.

После просмотра пользователь подтверждает конкретные материал/аккаунт/видимость: `ready → scheduled` либо `waiting_auth`. Время хранится UTC. Опоздание больше 10 минут требует явного возобновления. Перед сетевой записью `uploading` фиксируется отдельным commit. Потеря ответа/сбой процесса переводит в `unknown`; автоматический повтор отправки запрещён. Рендер и отправка выполняются одним исполнителем; закрытие вкладки им не управляет.

YouTube: OAuth Desktop, проверка ID текущего канала, `videos.insert` resumable, сохранение ID, отдельная проверка `uploadStatus`. Статус `published` в коде и «Обработан платформой» в UI означает успешную обработку, включая приватный материал. Открытость ролика определяется сохранённой настройкой, а не названием этого состояния. Фактическая публичная доступность требует отдельной проверки.

TikTok: установленный адаптер 1.2.0 принимает cookies в памяти, но возвращает bool без подтверждённого ID. Поэтому непроверенная сессия не разрешает отправку. Нельзя снять этот барьер присваиванием connected=true в базе и объявить интеграцию готовой. Следующий этап требует проверки аккаунта и ID на согласованном реальном материале.

## Метрики и обслуживание

YouTube Data API возвращает накопительные просмотры/лайки/комментарии. Каждый ответ сохраняется отдельным снимком; в таблице показывается последний, а не сумма. Отсутствующее поле — null, нулевой счётчик — 0. TikTok Display API требует отдельного токена/разрешений; браузерная сессия не заменяет их. Почасовое обновление и ежедневная копия выполняются worker; копия также создаётся при его запуске. Подробная историческая аналитика и проверенный пользовательский путь TikTok-метрик ещё не завершены.

Очистка через API касается только старых файлов из плоской папки `exports` у завершённых/отменённых заданий; оригиналы, неизвестные отправки, ожидающие публикации и секреты не удаляются. Автоматическое удаление по таймеру не включено.

## Дальнейшая проверка с пользователем

Нужны настоящие исходники и баннеры, вход Google и TikTok, конкретные часы и согласование тестовых отправок. Необходимо подтвердить загрузку/видимость/ID/метрики обеих платформ, поведение после сна/истечения доступа/потери сети, качество длинных роликов, аппаратный кодировщик и полный реальный день. Без этих проверок первая версия не считается принятой. Gemini остаётся отдельным согласуемым этапом.


## Дополнение: сводка и конкурентная отмена

`frontend/src/statistics.ts` выбирает последний снимок каждого ролика по абсолютному времени и собирает суммы/охват отдельно для аккаунтов. CSV сохраняет пустые значения, даты и источники; имена экранируются для таблиц. На странице доступны режимы роликов и каналов, фильтры платформ и аккаунтов; выгрузка охватывает все отфильтрованные страницы. Никаких выводов по одинаковому возрасту роликов пока нет: подтверждённое время публикации ещё не поступает.

Завершение рендера и запись ошибки в worker используют CAS `WHERE status = rendering`; ORM-чтение перед записью больше не может вернуть отменённую задачу в ready/failed. Непринятый после отмены результат удаляется. Проверка: `tests/test_quality.py::test_cancel_at_render_completion_keeps_cancelled_and_removes_orphan` с двумя исходами.


## Интерактивный вход TikTok и окно Windows

`backend/tiktok_login.py` запускает отдельный непостоянный Chrome. AUTH_TICKETS, ожидание, подтверждение и отмена сериализованы общим AUTH_LOCK с YouTube. Нужны неистёкшая sessionid, единственное @имя из собственной навигации/собственной страницы с редактированием и явное подтверждение пользователем. При подтверждении снова сверяются имя и сессия. Только после записи в DPAPI/SQLite устанавливается `connected=True, method=browser_login`. При сбое БД прежний секрет восстанавливается. HTTP-ошибки/URL/токены стороннего сайта в UI и логи не передаются. Пароли не читаются. Cookies/состояние других доменов не сохраняются.

`browser_login` и `browser_verified` — разные возможности: первая означает сохранённый вход с подтверждением профиля, вторая остаётся отдельным барьером адаптера отправки. Approval для browser_login возвращает понятную ошибку, а worker дополнительно блокирует старые approved-задания до сетевой записи. Это исключает ошибочное состояние unknown после одного лишь входа.

`scripts/desktop.py` — pywebview/WebView2, mutex по папке данных, фокус существующего окна, узкий JS-мост только для флага несохранённых правок. Не выполняем JS синхронно из FormClosing: это блокировало бы UI-поток. Native-прогон подтверждает редактирование/сохранение, MP4 и продолжение worker без окна. HTML/API отвечают no-store, URL окна включает SHA256 сборки index.html, чтобы старый профиль WebView2 не восстанавливал устаревшие кнопки.
