# FrameFlow — средние и «Истории», 07.11.2026

Внедрена и запущена первая рабочая версия расширения. Рабочие требования: `PROJECT_PLAN.md`; единственный чек-лист исполнения — дорожная карта в Obsidian SurvivalFlow. Это отчёт о проверках, а не отдельная дорожная карта.

## Что работает

- Статистика → Средние: отдельные платформы, каналы, период публикаций, просмотры/лайки/комментарии/средний ER для 1 ч / 24 ч / текущих значений, собственное n, медиана, сравнение с остальными роликами канала без самовключения, источники и приблизительность.
- Таблица `publication_stats` (схема 10) сохраняет рубежи независимо от последних 48 снимков. Время берётся из подтверждённых данных платформы, а не времени отправки/изменения задания. Для приватного YouTube время загрузки не принимается за время публикации. Без времени доступно «Всё время» с текущими счётчиками.
- Наблюдения около рубежа ограничены ±10 мин у часа / ±1 ч у суток и помечаются приблизительными; они не равны внутренней аналитике платформы. Worker раз в 5 минут проверяет известные приближающиеся рубежи/недавние задания; обычный часовой сбор сохранён. Сон Windows, отсутствие сети и подключение после рубежа не восстанавливают неизвестные данные.
- Истории: отдельный экран Precision Mono, 2/3 части, текстовые поля и импорт сценария, сохранение исходного импорта/версии/ID; настройки голоса, локальная библиотека фонов, готовая дорожка с границами, субтитры и выпуск. Последние сохранённые голосовые настройки предлагаются следующей истории.
- Google TTS: официальный Interactions API, Gemini 3.8 Flash TTS / Flash-Lite TTS, точный произносимый текст отдельно от стиля. Один явный запрос на часть, без автоматических повторов; кэш по входам, ошибки/отмена/прогресс и ограничение количества новых запросов. Секрет используется из существующего DPAPI-хранилища и не возвращается в UI.
- Субтитры: faster-whisper base на CPU/int8, времена по настоящему аудио; при достаточно близком распознавании исходный текст привязывается к наблюдаемым временам слов. При значительном расхождении сохраняется черновик распознавания. Перед встраиванием обязательны просмотр и явное подтверждение SRT; доступен импорт/экспорт и редактирование.
- Фоны: пакетная локальная загрузка, категории, выбор подходящего фрагмента с сохранёнными границами/хэшем, избегание недавних файлов при наличии альтернативы. Если подходящего длинного клипа нет, требуется другой файл либо явное разрешение цикла. Звук фона выключен, голос не ускоряется.
- Долгие операции идут в `story_tasks` через существующий независимый worker (схема 11). Изменение черновика во время обработки закрыто, проверка ревизии/активного задания выполняется в сериализованной транзакции. Прерванный платный запрос не повторяется автоматически; готовые части/кэш сохраняются.
- MP4 и SRT можно забрать отдельно; «Передать в монтажную» создаёт/повторно использует исходник с жанром story и названием части. Получатели, баннер, БУБА, видимость и расписание выбираются в существующем процессе. Сам перенос публикаций не создаёт. Несохранённые сценарий/SRT защищены от ухода из раздела и закрытия окна.

## Что ещё не принято

Пользовательская голосовая проба/предпочтительный тембр, собственный фон и полный художественный просмотр первой истории; реальный сбор возле будущих рубежей, физический сон Windows; отправка выбранной истории на конкретные аккаунты с согласованной видимостью/временем. Настоящие публикации и полный прежний FF-A1 не выполнялись и не закрыты. Не реализовывались последующие расширения: интернет-загрузка фонов, генерация сюжетов, несколько рассказчиков и аналитика форматов/частей.

## Как начать

Истории → Новая история → Импорт сценария (или текст каждой части) → Сохранить. Голос → выбрать профиль либо загрузить дорожку, при необходимости границы → Сохранить → Озвучить. Фон → добавить свои видео/выбрать категории. Субтитры → Распознать локально → проверить SRT → подтвердить и сохранить. Выпуск → выбрать размер/субтитры → Собрать MP4 → просмотреть → Передать в монтажную для баннера и обычного выпуска. Для быстрой технической пробы есть `docs/stories/example-wedding.txt`; озвучка точного примера с исходным профилем уже находится в локальном кэше.
