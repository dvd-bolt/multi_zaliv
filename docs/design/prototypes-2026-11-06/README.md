# FrameFlow — три новых прототипа

Созданы 6 ноября 2026 года по запросу пользователя. Это отдельные предложения для сравнения, а не утверждённая новая версия рабочего интерфейса.

Открыть `index.html` в браузере. Интернет и установка зависимостей для просмотра не нужны. На странице есть переходы в три полноценных интерактивных макета:

- **Studio** (`studio.html`) — тёплый графит, крупные карточки исходников на высоком экране, отдельные рабочие поверхности. Ближе всего к действующей классической «Монтажной».
- **Precision Mono** (`precision.html`) — выбранное пользователем направление; нейтральный графит, светлые акценты, непрерывные панели, компактный список материалов, более выраженный таймлайн. Версия макета 0.2 от 06.11.2026: синий оттенок убран, подписи исходников увеличены, радиусы полей смягчены. Медиа сохраняют исходные цвета.
- **Focus** (`focus.html`) — глубокие зелёные поверхности, подписанная навигация на широком экране, мягкие формы, объединённый блок каналов и запуска.

## Что можно попробовать

Выбор трёх исходников, воспроизведение 12-секундных фрагментов без звука, перемотку, баннер и время его показа, ширину и положение, оформление в диалоге, три цветовых пресета, четыре регулировки, отражение, «До / после», безопасную область, шесть демонстрационных каналов, название/описание/видимость, расписание и демоочередь. Есть образцы разделов «Каналы», «Статистика» и «Настройки».

Кнопка загрузки открывает локальные видео и изображения через браузер; в текущем макете видео заменяет выбранный исходник. Файлы никуда не отправляются. «Сохранить» запоминает параметры текущего ролика в локальном хранилище браузера; они доступны всем трём вариантам. Загруженные файлы и демоочередь не сохраняются после перезагрузки.

Видео, постеры и шрифты находятся в `assets/`. Для честного сравнения материалы и действия во всех трёх вариантах одинаковые. Каналы и метрики иллюстративные. Запросов к API FrameFlow, TikTok и YouTube нет; рендер и публикации не запускаются.

## Проверка

`verification.json` — результаты локальной проверки Chromium через установленный Playwright: 84 проверки, ошибок нет, 21 проверенная компоновка.

`finish-check.json` — ещё 13 успешных проверок: галерея на четырёх ширинах, reduced motion, отказ при нуле выбранных каналов и восстановление сохранённых настроек для каждого направления. Итого 97 проверок. Контрольные суммы всех файлов замороженного `design-v1` совпали с его manifest.

Для каждого направления проверены:

- 1440×900 и все три вкладки при 1024×600: нет вертикального/горизонтального переполнения и наложения настроек на блок запуска.
- 768×1024, 390×844 и 320×740: нет горизонтального переполнения; на узком экране допустима вертикальная прокрутка.
- Выбор исходника, ширина и текст баннера, цветовой пресет, клавиатурные вкладки, Escape и возврат фокуса, настоящее воспроизведение фрагмента.
- Ошибка несовместимой видимости и успешная постановка 18 вариантов в локальную демоочередь.

Механический детектор Impeccable по пяти файлам макетов вернул пустой список замечаний (`[]`). Это не подтверждение полного соответствия WCAG и не приёмка backend. Снимки интерфейсов — в `shots/`.

Повторить проверку: из корня проекта запустить статический сервер `python -m http.server 8795 --bind 127.0.0.1 --directory docs/design/prototypes-2026-11-06`, затем `node docs/design/prototypes-2026-11-06/verify.cjs`. Используется существующий Playwright из `frontend/node_modules` и локальный Chrome.

## Применение дизайн-скиллов

| Скилл                      | Применение в этой задаче                                                                                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Frontend Design            | Три самостоятельных направления с разными поверхностями, типографической иерархией и подачей исходников.                                                                                                                              |
| UI/UX Pro Max              | Поиск рекомендаций по плотному desktop-интерфейсу и видимому клавиатурному фокусу. Маркетинговая структура из общего генератора отклонена как неподходящая редактору.                                                                 |
| Impeccable                 | Режим Operate, сохранение действующих ограничений, quality floor, визуальная проверка и механический детектор. Сценарий выбора единственного нового бренда не применялся: заказаны сразу три прототипа внутри существующего продукта. |
| High-End Visual Design     | Точность поверхностей, геометрии и обратной связи. Декоративные приёмы для лендингов уступают требованию компактной монтажной.                                                                                                        |
| Redesign Existing Projects | Сохранены сценарий, порядок основных областей и границы существующего продукта; рабочий frontend не переписывался.                                                                                                                    |
| Design Taste Frontend      | Реальный интерфейс и проектные материалы, согласованная система, простые тексты. Hero-блоки, WebGL и маркетинговые секции не добавлялись.                                                                                             |
| Emil Design Engineering    | Стабильные состояния, клавиатура, быстрый отклик и отсутствие декоративного движения в часто используемых настройках.                                                                                                                 |
| Animate                    | Умеренная CSS-обратная связь на нажатие и уведомления; единая кривая, transform/opacity, учёт reduced motion и точного указателя.                                                                                                     |
| UI Lint                    | Токены вместо цветов в каждом компоненте, единые размеры/радиусы, отсутствие Tailwind-произвольных классов. Проверки, специфичные для StyleSeed, неприменимы к этому проекту.                                                         |

UI A11y и UI Motion изучены: они требуют окружение StyleSeed, которого здесь нет. Их специфичные команды, `data-slot` и motion seeds не выдаются за выполненные проверки. В макетах самостоятельно обеспечены нативные поля и диалоги, подписи, ARIA-вкладки, возврат фокуса и reduced motion.

Скиллы для Expo, Telegram, портфолио, 3D, scroll-storytelling, полиграфии и форм привлечения клиентов не относятся к локальной монтажной. Theme Factory не подменяет три запрошенных направления выбором одной готовой темы; Shadcn/Tailwind не добавлены ради стилизации прототипа. Использование всех взаимоисключающих правил одновременно исказило бы задачу.
