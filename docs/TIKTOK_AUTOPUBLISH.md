# Автоматическая отправка TikTok

Реализация: backend/tiktok_upload.py и backend/platforms.py.

1. Через обычный Chrome и расширение подключить свой профиль.
2. Создать MP4 и открыть готовое задание.
3. «Проверить и отправить в TikTok» → проверить материал, аккаунт, видимость → галочка разрешения → «Проверить и отправить сейчас».
4. Очередь должна быть запущена. Откроется служебное окно Chrome с сохранённой сессией. Не переключать в нём аккаунт.
5. Программа проверяет собственный профиль, форму, описание, видимость и сессию, загружает файл и нажимает публикацию. После положительного ответа с ID показывает ссылку и «Обработка платформой».

Если ошибка произошла до публикации, задание возвращается на проверку или просит подключение. После исправления нужно новое явное одобрение. Если результат после клика неизвестен, повтор запрещён: сначала сверить профиль. Ошибка подготовки не означает бан аккаунта.

Вход остаётся browser_login. Только положительный ответ операции публикации с ID подтверждает путь отправки (browser_verified). Он открывает обычные последующие и пакетные подтверждения; каждый новый ролик всё равно проверяет аккаунт и видимость.

Обработка и реальная видимость после приёма TikTok требуют отдельного подтверждения. Пока они не подтверждены, статус published не ставится. Статистика TikTok не получается автоматически из браузерных cookies.

Локальные проверки: 69 тестов, включая 15 проверок адаптера/очереди. Браузерный UI проверен 1024×600, запрос test_upload при проверке UI перехвачен и не публиковал материал. Результат реальной попытки записывается в журнал Obsidian отдельно.


## Исправление длинного описания TikTok — 27 октября 2026

Управляемый редактор вводит описание последовательно с задержкой 80 мс/символ. Для 220 символов нужно минимум 17.6 с, что превышало стандартный timeout страницы 15 с. Теперь для полного ввода выделяется max(15000, 100 × длина + 10000) мс; общий deadline подготовки уже учитывает размер описания.

Сверка текста нормализует NFC, служебные zero-width символы и количество пробельных символов между словами: редактор может представить абзац дополнительным переносом строки. Буквы, регистр, границы слов, текст хэштегов и emoji ZWJ по-прежнему проверяются; слияние/пропуск слов и изменение хэштега не разрешаются. Обработка неоднозначного ответа после нажатия публикации остаётся unknown без повторной отправки. Неизвестная ошибка подготовки до клика теперь содержит название этапа; в лог попадают только этап и класс исключения, без cookies, текста описания и удалённых ответов.

На сохранённом ранее разрешённом public-задании final_episode.mp4 → @labsclode исправлена подготовка, затем возобновлено только это TikTok-задание. Страница без авторизации подтвердила ID/автора/privateItem=false/playAddr, публичное описание совпало по проверяемому тексту. Worker сам перевёл задачу в published.
