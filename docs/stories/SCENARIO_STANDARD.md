# FrameFlow — стандарт сценария «Истории» v0.1

Дата: 07.11.2026. Статус: базовый контракт реализован — парсер, редактор, TTS, локальные субтитры и монтаж; пользовательская приёмка голоса/контента и публикаций остаётся отдельной. Основные требования: [PROJECT_PLAN.md](../../PROJECT_PLAN.md), раздел «7 ноября 2026 — средние и Истории». Исполнение отмечается только в дорожной карте Obsidian.

## Входные режимы

Основной: пользователь вводит готовый сценарий, программа озвучивает и собирает 2 или 3 части. Генерация самого сюжета не обязательна и в первую версию не входит. Дополнительный: пользователь загружает готовое аудио по частям либо одну дорожку с редактируемыми границами. Распознавание речи не считается уже доступной функцией.

## Пользовательский текстовый формат

```text
Название: За день до свадьбы
Частей: 3
Профиль голоса: Истории — основной
Фон: Мойка машин

[Часть 1]
За день до свадьбы я приехал к невесте раньше обычного.
Здесь продолжается произносимый текст первой части.

[Часть 2]
Здесь начинается произносимый текст второй части.

[Часть 3]
Здесь начинается произносимый текст заключительной части.
```

Названия полей и маркеры частей — служебные данные, их не передают в произносимый текст. В интерфейсе они представлены обычными полями и вкладками; текстовый импорт — удобный дополнительный способ. Поддержка CRLF/LF и UTF-8, включая BOM. Число частей должно совпадать с последовательными уникальными маркерами 1…N; пустая часть, повтор или пропуск номера дают понятную ошибку с местом исправления. Отсутствующие профиль/категория требуют выбора в интерфейсе; не подставлять неизвестные значения молча.

Никакого обязательного JSON для пользователя. Исходный импорт сохраняется, внутренние поля и ID хранятся структурированно. Примеры в этом документе иллюстративные, не готовый сценарий для публикации.

## Структура истории

Вся история: стабильный ID, название, язык `ru`, версия, число частей, выбранный голосовой профиль, категории фона и состояние. Каждая часть: стабильный ID, номер, произносимый текст, отдельное название/описание публикации, аудио, длительность, субтитры, выбранный фрагмент фона, MP4 и связи с существующими заданиями публикаций. Для материалов сохраняются происхождение и контрольные суммы.

Первая версия — один рассказчик, один профиль на историю. Диалоги можно передавать тому же рассказчику; отдельные актёрские голоса и переключения персонажей — последующее расширение.

Смысловая схема для трёх частей: завязка/открытие → последствия/поворот → действия/развязка. Для двух частей середина объединяется с соседними участками. Каждая часть содержит законченные предложения; последняя завершает сюжет. Программа может предложить границы, пользователь может их исправить. Утверждённый текст не переписывается автоматически.

## Длительность и готовое аудио

60–90 секунд на часть — начальный ориентир для эксперимента, не жёсткая валидация, не правило платформ и не обещание монетизации. Перед TTS показывать приблизительную длину, после — измеренную через ffprobe. Переполнение ориентира решать редактированием текста/границ, без скрытого обрыва, ускорения или удаления фраз.

Для одной готовой дорожки границы задаются по времени, предложенные паузы остаются редактируемыми. После сборки не теряются и не повторяются слова на стыках. При наличии текста использовать выравнивание по аудио; без текста субтитры требуют отдельно проверенного распознавания. Монтаж готового аудио без субтитров можно проверять до готовности распознавания, но он не закрывает приёмку субтитров.

## Голосовой профиль

Хранить провайдера, конкретный ID модели, имя/ID голоса, короткий стиль, язык и версию настроек. Отдельно отмечать, прослушан и выбран ли профиль пользователем. Модель, голос и стиль всегда явно отображаются в задании озвучки; секреты не входят в профиль/экспорт.

Конкретный голос и модель выбираются короткой пробой при интеграции. Варианты из процесса «Банерки» — исходная точка, не доказательство утверждения голоса для нового формата. Доступность модели, API, лимиты и формат ответа проверяются перед реализацией адаптера.

Каждая часть озвучивается отдельно. Имена экспорта: `part-01.txt`, `part-01.wav`, `part-01.srt`, `part-01.mp4` и аналогично для следующих частей; файлы размещаются в папке стабильного ID истории/версии, чтобы одинаковые названия не перезаписывали друг друга. Большую часть разрешается озвучивать блоками с сохранением порядка и проверкой стыков; в интерфейсе она остаётся одной частью.

## Изменения и повторные операции

- Изменение текста одной части помечает устаревшими только её озвучку, субтитры и MP4; остальные части переиспользуются.
- Изменение модели/голоса/стиля меняет ключ кэша затронутых частей. Замена фона не требует нового TTS. Изменение оформления субтитров не требует нового аудио или распознавания.
- Ключ кэша TTS включает точный текст, провайдера, модель, голос, стиль, язык и версию адаптера/настроек. Сохраняются параметры реально выполненной генерации.
- При отмене/перезапуске готовые артефакты проверяются и сохраняются. Число новых запросов/попыток видно перед запуском; расходы и повторные попытки ограничены настройками.
- Опубликованные материалы и уже созданные задания не переписываются вслед за правкой черновика. Новая версия требует явного выбора для выпуска; действуют существующие проверки от повторной отправки.

## Проверка контракта при реализации

Нужны сценарии на 2/3 части, ошибки маркеров/пустых полей, кириллицу/пунктуацию, неизменность произносимого текста, отсутствие служебных заголовков в TTS, порядок частей и изолированную перегенерацию. Настоящее аудио прослушивается отдельно: смысл, дикция, окончания фраз и стыки нельзя принять только по ответу HTTP 200.
