## Предложение по статистике

Новая внутренняя вкладка «Средние» рядом с «Ролики», в действующем Precision Mono. Фильтры: платформа, канал, период публикации роликов. «Период» выбирает когорту публикаций, а не прирост счётчиков за календарный период. Платформы никогда не объединяются в одно среднее.

Таблица: строки «Просмотры / Лайки / Комментарии / ER»; столбцы «Первый час / Первые 24 ч / Сейчас». Для каждой метрики собственное n — количество роликов с пригодными данными. Опциональная медиана просмотров показывает типичный результат при наличии отдельных хитов. Сравнение выбранного ролика за 24 часа со средним остальных роликов своего канала; сам выбранный ролик из базы сравнения исключён.

В интерактивном макете все значения и названия примеров демонстрационные; подключения к рабочей базе нет. Путь: `C:\Users\dvd\.codex\visualizations\2026\11\07\01a1b758-a666-7991-a632-ae32d2946830\frameflow-averages.html`. HTML возвращается пользователю прямо в чате. Фильтры меняют локальный набор примеров; это не реализованный сбор статистики.

Правила будущего расчёта:

- Среднее — сумма доступных значений / число пригодных роликов. Неизвестное не заменяется нулём; настоящее значение 0 участвует. Показывать актуальность, источник и полноту.
- «Первый час» — накопленный результат к возрасту 1 час, а не текущая скорость и не сумма снимков. Первые 24 часа — тот же принцип. Младшие ролики не участвуют в ещё не достигнутом рубеже.
- Нужен подтверждённый момент публикации, не начало отправки и не изменение задания. При неизвестном времени возрастные метрики недоступны; текущие счётчики могут оставаться доступными.
- Отдельно хранить контрольные значения 1 ч / 24 ч: время реального наблюдения, источник и качество. Предлагаемый начальный допуск для ближайшего наблюдения — ±10 минут у часа и ±1 час у суток; такие значения маркировать приблизительными. Допуски ещё не утверждены. Снимок далеко от рубежа не считать результатом ровно за час/сутки; интерполяцию разрешать только с явной маркировкой и ограничением разрыва.
- ER каждого ролика = 100 × (лайки + комментарии) / просмотры; затем среднее ER по пригодным роликам. Если просмотры 0 либо неизвестны лайки/комментарии, ER неизвестен. Взвешенный ER по суммам — другая метрика, её не подменять средним ER. Репосты не включены, формула видима.
- «Сейчас» объединяет последние известные счётчики роликов разного возраста, поэтому не используется для утверждения, что один ролик стартовал лучше другого.
- В будущем разделять форматы «анимация / истории», части серии и при необходимости длительность; сравнение разных форматов без фильтра может вводить в заблуждение. Для нового формата без данных показывать отсутствие выборки.

Фактические ограничения найденного кода:

- `frontend/src/Stats.tsx`: «В час» делит просмотры на возраст; `day1` берёт последний снимок до 24 ч без близости к рубежу. Время возраста — `upload_started_at || updated`, что не равно подтверждённому моменту публикации. Для новой аналитики эти значения нельзя без проверки использовать как точные контрольные показатели.
- `backend/youtube_library.py`: для внешних роликов сохраняются последние 48 снимков. Ранние наблюдения могут исчезать; контрольные значения должны переживать очистку истории.
- Новые средние не восстановят неизвестные ранние значения старых публикаций. Более частый локальный сбор при закрытом приложении/сне также требует отдельного решения и проверки.

## Предложение: раздел «Истории»

Два входа в один процесс:

1. **Из сценария:** текст → проверка частей → короткая проба голоса → озвучка → субтитры → фон → предпросмотр → MP4 → действующая очередь по действию пользователя.
2. **Из готовой озвучки:** аудио → длительность и паузы → предложенные/ручные границы частей → субтитры при наличии текста или отдельного распознавания → тот же монтаж. Для надёжной первой версии можно загрузить аудио по частям. Распознавание и точное выравнивание слов — отдельная работа, не обещанная возможность существующего TTS.

Первый экран: список историй с частями. Внутри выбранной истории — «Сценарий / Голос / Фон / Выпуск» и предпросмотр, в языке Precision Mono. Дополнительные настройки и длинные списки не перегружают рабочую область 1024×600. Старый монтажный процесс остаётся самостоятельным.

### Сценарий v0.1 — предложение

Пользователь работает с обычным русским текстом, без обязательного JSON. Метаданные и заголовки частей отделены от произносимого текста.

```text
Название: За день до свадьбы
Частей: 3
Профиль голоса: Истории — основной
Фон: Мойка машин

[Часть 1]
За день до свадьбы я приехал к невесте раньше обычного...
...

[Часть 2]
...

[Часть 3]
...
```

Одна история хранится как связанная сущность, части — дочерние. Каждая часть: ID, произносимый текст, заголовок публикации, профиль голоса, аудио, субтитры, фон/фрагмент, MP4, статус и связи с публикациями. Последняя часть имеет завершённую развязку. Продолжение должно быть осмысленным, а не случайной обрезкой посреди предложения.

Предлагаемая структура трилогии: 1 — хук, завязка, открытие и вопрос; 2 — последствия, обострение и поворот; 3 — действия героя, развязка и финал. Для двух частей объединить средний участок. Длительность не выводить строго из числа символов: сначала ориентировочный прогноз, затем реальная речь и корректировка границ с подтверждением пользователя. Начальный эксперимент — 2–3 части примерно по 60–90 с, это творческий ориентир, не требование платформ и не гарантия монетизации.

Модель, конкретное имя голоса и короткий стиль фиксируются в профиле; настройки не меняются молча между частями. В памятке банерки и `shared/voices.json` имеются предложения Gemini 3.8 Flash TTS / Orus и Charon; метаданные явно не подтверждают прослушивание/утверждение конкретного тембра. Для нового формата предложить самостоятельную короткую пробу. Пример начального профиля: `gemini-3.8-flash-tts`, `Orus`, «Разговорный русский рассказ от первого лица, сдержанная эмоциональность, естественные паузы, чёткая дикция». Файл текста `part-01.txt`, результат `part-01.wav`; аналогично для следующих частей. Этот профиль ещё не выбран пользователем.

Официальная документация Google поддерживает управляемую озвучку и выбор голосов; API, лимиты и доступ конкретного аккаунта проверяются при интеграции. Ключ существующего Gemini не считать автоматически подтверждённым доступом к TTS. Платные запросы в рамках обсуждения не выполняются.

### Фоновая библиотека

Начать с пакетной загрузки пользователем своих/разрешённых фоновых видео, с категориями «Шарики / Ковры / Машины». «Случайный» означает случайный подходящий клип и стартовый фрагмент внутри выбранных категорий. Автоскачивание из интернета — отдельный этап: нужен выбранный источник и его условия, оно не считается готовым.

Фон обрезается под настоящую длительность речи, приводится к вертикальному формату с предпросмотром кадрирования. Исходный звук фона по умолчанию выключен. Если клип слишком короткий — взять следующий подходящий или явно разрешённый цикл, без скрытого ускорения речи, растягивания или обратного проигрывания. Сохранять ID файла, хэш, точки начала/конца и выбранную случайность. Повторный рендер воспроизводим; смена фона — отдельное действие.

### Полезные дополнения в порядке пользы

- Субтитры с переносами для телефона, безопасными отступами и выделением текущей фразы. Тайминги привязаны к настоящему аудио, не к равным долям длины текста; локальное выравнивание/распознавание выбирается и проверяется отдельно.
- Кэш озвучки по тексту, модели, голосу и стилю; изменение одной части не требует повторять всё. Понятное число новых генераций и лимит расходов/попыток до запуска.
- Защита от недавних повторов фона и список использованных фрагментов.
- Нумерация частей и порядок публикаций, предпросмотр всего пакета; существующие правила отправки и неизвестного результата сохраняются.
- Аналитика по формату и номеру части; затем по типу фона и голосовому профилю. По отдельным роликам не заявлять причинность или гарантированный рост. Удержание и переходы между частями показывать только при наличии настоящих данных.
